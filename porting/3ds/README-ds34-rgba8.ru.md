Цель: проверить, завершит ли настоящий DS34 GPU backend draw/present через аппаратно успешную в stock simple_tri цепочку RGBA8/32-bit fill → RGB8. Это синтетический тест без Dead Space engine, APK, оригинальных ресурсов и RX/native-entry-point кода. Исходный backend, SDK и старые CPU/GPU сборки не изменены.

## Только после отдельного согласования запуска

1. Сохранить имеющиеся GPU-логи с SD. Если папка `SD:/3ds/ds34-rgba8-v0.1.0/` уже существует, скопировать её на компьютер: при старте программа удалит свои прежние result/exit/frame/queue файлы и перезапишет свой лог. Остальные папки не используются.
2. Скопировать **только новую CIA** на SD и установить через FBI обычным способом. Никакие игровые ресурсы для теста не нужны. Проверить HOME название **DS34 RGBA8 v0.1.0**, а не прежний DS34 GPU Test. Открыть приложение **один раз** на New Nintendo 3DS/XL либо New 2DS XL.
3. На нижнем экране должны быть `DS34 RGBA8 -> RGB8 v0.1.0`, `A: run nine frames once`, предупреждение о возможном зависании. До A GPU-тест не начинается; START выходит без теста. Верхний экран до A не является результатом отрисовки.
4. Нажать **A один раз**. Первый кадр: голубой фон RGB(104,176,216), белый прямоугольник64×80 в нижней левой части (x40…103, y40…119 при отсчёте y снизу). Нижний экран напечатает `First DS34 frame PASS`. Затем прямоугольник перемещается вправо и меняет красный/зелёный/синий цвет. Всего9 кадров; последние3 одинаковы. Финал — синий прямоугольник x232…295, верхняя граница на середине экрана, на том же голубом фоне. Сохраняется именно финальный кадр, без бесконечной анимации. Не оценивать FPS по скорости этого теста: чтение и запись SD намеренно его замедляют.
5. Успех: нижний экран **`DS34 TEST PASS: 9 frames`**, изображение соответствует описанию, после **START** штатный возврат HOME. Зафиксировать фото обоих экранов и отдельно сообщить, вернулся ли START в HOME. Числа в result.json и фактический выход — разные части проверки.
6. После завершения/восстановления скопировать целиком `SD:/3ds/ds34-rgba8-v0.1.0/`: `gpu-test.log`, `result.json`, `exit.txt`, `queue-*.json`, `frame-*.json` и `frame-*.raw`. Сохранить даже неполную папку после зависания. Отсутствие result.json тоже результат, его не заменять старым файлом. Не повторять запуск автоматически после ошибки.

## Зависание возможно

Проверка Azahar не гарантирует завершения на железе. Сохранены штатные **блокирующие** SYNCDRAW/FrameSync, FrameEnd и первоначальная загрузка нейтральной текстуры. GSP, SD, APT и Fini также могут блокироваться. Таймаута, способного безопасно остановить GPU, нет; START может не читаться, если основной поток уже заблокирован. При полном зависании может понадобиться удержание POWER до выключения; использовать обычное для своей приставки восстановление, затем сохранить SD-диагностику. Повторный запуск этой же версии без нового решения не нужен.

Если управление ещё работает, но SDK queue занята, START напечатает `GPU busy. Memory retained`; память не освобождается и C3D_Fini не вызывается до idle. Это предотвращает намеренное освобождение занятых buffers, но не гарантирует восстановление или безопасный выход при реальном аппаратном stall. Последний PHASE в логе обозначает достигнутый участок; он сам по себе не определяет зависшую GPU-команду. Суммарные counters не являются идентификаторами IRQ.

## Что проверено программно

Azahar2126.2 Software, NCCH из **этой CIA**,9 кадров/9 draws/18 triangles; каждый кадр целиком проверен по96000 пикселей в настоящем BGR8 CTR layout, raw288000 bytes. Семь уникальных кадров, последние3 идентичны. Девять очередей FILL/PICA/DISPLAY завершились3/3; отдельная начальная TEXCOPY256 bytes —1/1. Ошибок GLES/invalid-memory-access и vertex/texture audit mismatch нет. A gate, удаление stale result и guest START → GSP ReleaseRight/free heap проверены до host unload. Frontend shutdown callback не используется как доказательство HOME, установка FBI в эмуляторе не воспроизводится. Cache service stubs остаются; native cache coherence и HOME проверяются только реальным результатом пользователя.

Путь: target240×400 RGBA8/D24S8, clear0x68B0D8FF, FILL controls0201/0201, color/depth384000/384000 bytes; transfer dimensions019000f0→019000f0, flags00001000 (RGBA8→RGB8, flip/raw/tiled/scaling0); TOP GSP_BGR8_OES, DS13 layout1, present/invalidate/capture288000 bytes. Эти значения проверены по реальным GX argument words новой сборки и исходникам pinned SDK/stock. Реальные GX/native-address captures рабочего stock аппаратного запуска отсутствуют; идентичность его runtime addresses не утверждается.

От stock отличаются DS34 shader/vertex stream/GLES/scissor и2 triangles вместо1, нейтральная текстура/дополнительные allocations, RGB-only write mask с alpha1, подготовка FrameDrawOn до clear с FrameSplit, явный present с дополнительным FrameSync/Begin и CPU readback, A gate/BOTTOM console/SD диагностика. GPU/IRQ callbacks и SDK wait semantics сохранены. Run/Clear wrappers записывают только ограниченные atomic memory records, без I/O в callback; их сохранение на SD выполняет main thread. Модифицированная копия DS34 находится только в отдельной build directory; исходный `3ds/source/ds34_gpu_3ds.c` не изменён.

PASS на железе разрешит следующим этапом готовить настоящий кадр Dead Space через отдельный native entry point. Этот тест ещё не проверяет живой движок, игровые textures,3D-сцену, high-FCRAM178MiB layout, stream rollover, управление или звук.
