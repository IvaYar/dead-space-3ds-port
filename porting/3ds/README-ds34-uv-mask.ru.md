# DS34 UV Mask 0.2.1 — один фактор PICA

Подготовленная экспериментальная CIA, **на настоящей 3DS не испытана**. Запуск требует отдельного согласования с пользователем. Рабочий официальный simple_tri и прежний DS34 GX Watch сохранены.

Меняется только запись двух UV-выходов vertex shader: `xy → xyzw`. В SHBIN оба выхода объявлены с mask `0xF`; раньше инструкции записывали mask `0xC`. Новая сборка записывает каждый компонент каждого объявленного выхода ровно один раз. Полезные `xy`, shader instructions, uniforms, output mapping и все остальные параметры прежние. Это проверка конкретной гипотезы о незавершённом выводе VSH; аппаратная причина прежнего отсутствия P3D ещё не доказана.

Исходная правка:

```diff
-    mul uv0_out.xy, texture_scale.xy, uv0_in.xy
-    mul uv1_out.xy, texture_scale.zw, uv1_in.xy
+    mul uv0_out, texture_scale.xy, uv0_in.xy
+    mul uv1_out, texture_scale.zw, uv1_in.xy
```

Picasso меняет ровно два байта operand descriptors SHBIN. Их замена в единственном встроенном SHBIN сохранённого ELF позволяет сохранить CPU instructions, адреса/размеры/lifetime ресурсов и диагностический observer побайтно. ARM-код не перекомпилируется. DWARF остаётся от исходного ELF; отдельный shader source и manifest описывают замену. CIA имеет отдельную identity: **TitleID 000400000FDE6F00**, Product **CTR-H-D3UM**, HOME **DS34 UV Mask 0.2.1**, title version 1.

**Экран и файлы по-прежнему сообщают GX Watch 0.2.0.** Это намеренно: runtime strings и observer сохранены для изоляции фактора. SD root также прежний: `SD:/3ds/ds34-gx-watch-v0.2.0/`. Каждый запуск создаёт новую свободную `run-NNNN/`; прежние папки не переписываются. Идентифицировать тест по HOME title/TitleID, CIA hash из manifest и новому номеру run, а не только по версии в result.json.

Azahar Software PASS: реальный NCCH из этой CIA; все 96000 BGR8 pixels совпали с прежним кадром, PSC0/P3D/PPF=1/1/1, queue=3/3/3, GL0, invalid accesses0, START завершил guest cleanup. PICA1168 bytes отличается от аппаратного dump только байтами `0xF0` и `0xF4`: descriptors `000542AC→000542AF`, `000557EC→000557EF`. Все 24 GX words, включая адреса, совпали. Эмулятор не проверяет исследуемое аппаратное зависание.

После отдельного согласования предлагается **один** пользовательский запуск этой CIA: открыть из HOME, нажать A один раз, сохранить TOP/BOTTOM и всю новую run-NNNN, затем проверить START. Ожидается белый прямоугольник на голубом фоне, events1/1/1, queue3/3/3, Pixel check OK и возврат в HOME. Повторно старую GX Watch запускать не требуется.

| Результат единственного теста | Значение |
|---|---|
| P3D+PPF, queue3/3/3, правильный кадр и START→HOME | Поддерживает причинность неполной записи UV; затем перенести те же две shader-правки в DS34 и готовить отдельный native game entry point |
| Прежние PSC0=1/P3D=PPF=0, queue3/3/1 | Полная запись UV не устраняет отказ; гипотеза единственной причины опровергнута |
| P3D появился, но PPF/кадр/выход неполны | PICA продвинулась; весь rendering path ещё не подтверждён |
| Остановка до окна/нет надёжных файлов | Результат недостаточен для проверки shader-гипотезы |

При busy/неполных completion observer удерживает GPU memory и откладывает выход. Как и в исходном тесте, может потребоваться POWER; нового механизма восстановления нет. Автоматический повтор не предусмотрен. Игра и ресурсы игры в пакете отсутствуют.

Воспроизведение подготовки: `python porting/tools/build_ds34_uv_mask.py`, затем `python porting/tests/smoke_ds34_uv_mask.py`. Скрипты отказываются переписывать завершённую сборку/эмуляторные результаты. Существующие baseline не пересобираются. Полный разбор — `porting/analysis/ds34-uv-mask-v0.2.1/report.ru.md`.
