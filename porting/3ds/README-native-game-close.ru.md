## Будущий согласованный аппаратный тест

Одна CIA, максимум два запуска; при первом новом зависании не повторять ради дополнительных данных.

1. Запустить именно **DS Game Close 0.1.3**, нажать **A один раз**. Дать пройти заставкам. Если получен FRAME FAIL, дождаться автоматической очистки и возврата в HOME. Если получен FRAME + SEQUENCE SAVED, нажать START один раз для выхода. Записать время ожидания и последние сообщения.
2. Только после нормального завершения первого запуска: запустить снова, A один раз. После анимаций, на изображении с Айзеком/наушниками, нажать **HOME один раз**. Дождаться завершения очистки и появления HOME Menu; затем выбрать приложение и нажать **X**, подтвердить закрытие. Записать время от HOME до меню и от X до окончания закрытия. Возврат в игру после HOME здесь не возобновляет renderer: это завершённый checkpoint.

Если появилась надпись STOPPED/FAIL, сфотографировать оба экрана и записать время ожидания. Повторные HOME/POWER не использовать как диагностические шаги; если они понадобились для восстановления, сообщить их последовательность и было ли удержание POWER. Произвольный hardware hang не обещан безопасно прерываемым.

## Программное воспроизведение

Существующие evidence/build не перезаписываются. Для повторения проверенного CXI можно выбрать новый `--attempt`, например:

```powershell
$env:PYTHONDONTWRITEBYTECODE = '1'
python porting/tests/smoke_native_game_close.py --variant late --cycles 2 --attempt review1
python porting/tests/smoke_native_game_close.py --variant latestopped --cycles 1 --attempt review1
```

Это создаёт только новые isolated SD с общими immutable assets и собственными writable файлами. Старый runner не меняется. Current release gate привязан к сохранённой финальной матрице, а не к произвольному новому `attempt`:

```powershell
python porting/tools/audit_native_game_close.py
```

`--cia` повторно запрещён, когда кандидат уже существует. Не удалять его для обхода защиты. Для следующей реализации нужны новая версия и новый каталог сборки.
