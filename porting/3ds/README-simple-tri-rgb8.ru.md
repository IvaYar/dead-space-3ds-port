# simple_tri RGB8 → RGB8 v0.1.0

Резервный минимальный тест, **на приставке не запускался**. Подготовлен по запросу30.10.2026; аппаратный запуск текущим запросом запрещён. Для продвижения DS34 предпочтительнее уже подтверждённый RGBA8 → RGB8; этот тест не является обязательным этапом.

Гипотеза: сохранится ли аппаратный отказ RGB8 source/24-bit clear без RGB565 output и поздней смены TOP? За основу взят сохранённый нерабочий RGB8 → RGB565. Меняется только выходная конфигурация в двух согласованных местах: transfer output → RGB8 и удаление TOP RGB565 switch. Target RGB8, clear0x0068B0D8, shader object, SYNCDRAW, draw, SDK и capabilities прежние. Flags0x1100. Подробный diff и manifest приложены.

CIA TitleID `000400000FDE6C00`, Product `CTR-H-C3DR`, title version1, HOME имя **tri RGB8 v0.1.0**. Это отдельный тест; рабочий stock и старый RGB565 сохраняются. Игры, APK, оригинальной .so, ресурсов и SDK в архиве нет.

Ожидаемый вид: белый треугольник на голубом фоне RGB(104,176,216); START возвращает HOME. Программа начинает рисовать сразу, без A gate/SD logger/timeout, как исходный пример. Новый emulator PASS не подтверждает аппаратную работоспособность. Инструкции запуска на железе в этом сеансе не выполняются.

Возможные результаты: правильный кадр и выход сузят отличие к RGB565 output/TOP switch; повтор зависания оставит RGB8 source/fill/transfer неподтверждёнными. Кадр с нарушениями или без нормального выхода — частичный результат. Ни один из них сам по себе не определяет конкретную зависшую команду и не доказывает готовность игры.

Подготовка: `python porting/tools/build_simple_tri_rgb8.py` (откажется перезаписывать существующую build directory), затем один программный контроль `python porting/tests/smoke_simple_tri_rgb8.py`, упаковка `python porting/tools/package_simple_tri_rgb8.py`. Эти команды не запускают приставку. Уже выполненную проверку без новой причины не повторять.
