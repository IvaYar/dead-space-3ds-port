# Проверка на компьютере до следующей установки на консоль

Пользователь попросил объединять промежуточные проверки и не просить переставлять карту после каждого небольшого этапа. Этот порядок принят: сначала ARM-проверки и Azahar, затем отдельная аппаратная проверка при существенном новом результате. Подтверждённый `STAGE 8 PASSED` сохранён в `analysis/hardware/stage8-v0.8.0-user.log` с SHA-256 в соседнем JSON.

**Текущий результат после системного bootstrap:** пройдены EAIO и `SystemAndroidDelegate`, первый `NativeOnDrawFrame` вернулся. На втором вызове ранняя диагностика сообщает об отсутствующем адаптере акселерометра. Изображения игры ещё нет. Прошли 158 ARM-проверок и семь сценариев Azahar. Подробности и актуальные команды — [PLATFORM-BOOTSTRAP.ru.md](PLATFORM-BOOTSTRAP.ru.md). Установка на приставку пока не требуется. Описанные ниже первые остановки сохранены как история.

## Первая попытка: сохранённая история

Первая инструментированная попытка запуска оригинальной библиотеки выполнена в **Azahar**, а также независимо в CPU-эмуляторе **Unicorn ARM11 MPCore**. Результаты совпадают по пройденным функциям и месту остановки:

| Блок работы | Результат на компьютере |
| --- | --- |
| Память собственного аллокатора игры | Добавлены отдельный sbrk-буфер, private anonymous RW mmap и munmap; прошли 14 новых проверок, включая реальный softfp-модуль с шестью аргументами mmap. |
| Инициализация оригинальной библиотеки | Все **209** конструкторов завершились. Ничьи тела не пропускались. |
| Начальный JNI | Проверено тело `JNI_OnLoad`, получено `00010004`, сохранённый JavaVM совпал. |
| Первая попытка старта | Вернулись `NativeOnCreate`, `NativeOnSurfaceCreated`, `NativeOnSurfaceChanged`. Выполнение вошло в `NativeOnDrawFrame` и остановилось на первом неподдержанном JNI-вызове. |

Конкретная остановка:

```text
STOP unsupported: JNI FindClass (slot 6)
Phase: NativeOnDrawFrame
Caller offset: 00236808
Requested class: com/ea/EAIO/EAIO
```

После этой остановки был добавлен Java-адаптер EAIO и требуемый ему набор JNI. **Меню и кадр игры пока не отрисованы.** Вход в функцию кадра сам по себе не означает работу движка или графики.

Свидетельства первой остановки сохранены в `analysis/engine-baseline/`. Текущий журнал Azahar: `analysis/azahar-smoke/engine-present.log`, трассировка: `analysis/engine-first-entry-experiment.json`, сводка: `analysis/engine-progress.json`. К 122 прежним ARM-проверкам добавлены 20 проверок JNI; Azahar теперь проверяет также отсутствующий и повреждённый ресурс.

## Что делает инструментирование

Обычный загрузчик по-прежнему отказывается полностью связывать игру при отсутствующих обязательных импортах. Для экспериментального runtime доступно **152** привязки донора: прежние 149 плюс три API памяти с указанными ниже ограничениями. Остаются **236 обязательных и четыре слабых**. Проверка отказа подтверждает, что образ не меняется.

Только после этого отдельный эксперимент связывает неизвестные функции с ловушками, которые **завершают выполнение**, записывая имя и место вызова. Они не возвращают фиктивный успех и не учитываются как реализованные импорты. Для неизвестных JNI-слотов используется такой же отказ. Неизвестные данные не заменяются адресом функции: отдельно предоставляется хранилище stack canary, отмеченное как часть эксперимента.

В Unicorn время обеспечивается компьютером; в Azahar для `clock` используется явно обозначенное время эмулятора. Это не реализация native process CPU clock для 3DS и не измерение производительности игры. Этот сервис также исключён из числа 152 готовых привязок.

Новые модули не исправляют инструкции оригинального движка и не используют смещения патчей от несовпадающей Vita-библиотеки. Проверяется исходный SD-донор SHA-256 `dd42272365d0abd8ad9c89450bb7f869ee4ac0ad548525758e6a1e7df4d3c1eb`. Существующий механизм RX/кэша совпадает с проверенным на устройстве этапом 8.

## Память и ограничения

Донор использует собственный аллокатор поверх sbrk/mmap. Для него выделяются две раздельные арены по **20 MiB**; они не пересекаются с native newlib heap и не подменяют его program break. sbrk возвращает прежнюю границу, допускает рост, уменьшение и запрос текущего значения. Переполнение и выход за пределы арены возвращают ENOMEM без изменения границы.

mmap поддерживает только `PROT_READ|PROT_WRITE`, `MAP_PRIVATE|MAP_ANONYMOUS`, fd=-1, offset=0. Размер округляется до страницы, память обнуляется при каждом выделении. munmap освобождает целые страницы, включая часть диапазона; повторное освобождение пустого участка не портит счётчики. Файловые, shared, fixed и другие режимы защиты возвращают ошибку; они не имитируются обычным writable-буфером. Учёт защищён общей блокировкой runtime.

До остановки оба эмулятора зафиксировали **16 781 312 байт sbrk** и **4097 страниц mmap** — суммарно около **32,008 MiB** занятого пространства этих арен, без отказов выделения. Это не общий расход памяти процесса: сюда не входят загруженная библиотека, её исходный файл, native heap, framebuffer и прочие объекты.

Эксперимент не проверяет GLES/PICA200, звук, исключения C++ и полноценный Android lifecycle. Чтение файлов через выбранный JNI-набор теперь проверено отдельно. Графические вызовы пока остаются ловушками. Исполнение всей библиотеки с native RX на консоли ещё не проверено: существующий аппаратный учёт ограничен 16 страницами, а для полного модуля понадобится другая организация учёта исполняемых диапазонов. Ветка Azahar не проверяет эти права.

## Как повторить

Из корня проекта:

```powershell
python porting/tools/build_emulator_runtime.py
python porting/tests/test_emulator_runtime.py
python porting/tests/test_jni10.py
python porting/tools/run_engine_experiment.py
python porting/tests/smoke_engine_azahar.py --case ready
python porting/tests/smoke_engine_azahar.py --case missing
python porting/tests/smoke_engine_azahar.py --case wrong
python porting/tests/smoke_engine_azahar.py --case asset-missing
python porting/tests/smoke_engine_azahar.py --case asset-wrong
python porting/tests/smoke_engine_azahar.py --case present
```

`tools/check_engine_progress.py` проверяет совпадение свидетельств, SHA-256 сборки и формирует сводный отчёт `analysis/engine-progress.json`.

Создаются `3ds/build-emulator/core-test.elf` для Unicorn и **`engine-audit.cxi` для Azahar**. CIA не создаётся. CXI содержит явный отказ работы вне эмулятора, ловушки и диагностические модели; он не является новой сборкой порта для установки на приставку. Пользовательскую карту и прежний CIA менять не нужно.

Пакеты этапов 1–8 оставлены прежними. Их исторические build-manifest не переписываются задним числом; новые аппаратные подтверждения сохраняются отдельно. Для дальнейшей работы нужны адаптер акселерометра/HID, оставшиеся операции EAIO, продолжение трассировки запросов движка и графический слой. Число «4–6 этапов» было предварительной оценкой объёма, а не гарантированным числом проверок до меню игры.
