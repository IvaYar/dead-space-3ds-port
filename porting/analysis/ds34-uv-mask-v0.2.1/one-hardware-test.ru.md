# Подготовка одного пользовательского аппаратного испытания

31.10.2026 пользователь согласовал подготовку к одному аппаратному испытанию DS34 UV Mask v0.2.1 и запросил инструкцию. Агент проверил существующий пакет без пересборки, новых emulator runs, аппаратного запуска и push. Повтор при FAIL и дополнительные аппаратные тесты не разрешены. Машинный результат проверки: `preflight-one-hardware-test.json`.

## Подтверждено перед выдачей инструкции

- Сравнение с DS34 GX Watch0.2.0: ELF той же длины, различия только `35C44:AC→AF`, `35C4C:EC→EF`, внутри embedded SHBIN. CPU code, addresses, allocation sizes, lifetimes, observer и строки прежние.
- SHBIN той же длины280 bytes: только descriptors `000542AC→000542AF` и `000557EC→000557EF`, то есть maskC→F для UV0/UV1. Instruction words, DVLE, uniforms, sources/swizzles, maps/clocks не меняются.
- В CIA изменена diagnostic identity: TitleID000400000FDE6F00, ProductCTR-H-D3UM, HOME DS34 UV Mask0.2.1; связанные container hashes/signatures/compression также закономерно отличаются. Capabilities, memory profile и stack сохранены. Не утверждать, что сама CIA отличается только двумя байтами.
- Для всех четырёх выходов (position, color, UV0, UV1) декодированы counts x/y/z/w=1/1/1/1. Других объявленных выходов нет; flow control нет, END один. Пропущенных или повторно записанных объявленных компонент нет.
- CIA в ZIP побайтно совпадает с CIA, уже прошедшей Azahar. Все ZIP entry hashes и145 прежних baseline/evidence файлов повторно проверены. Готовый ZIP/CIA не изменялись.
- `make_folder` создаёт первую свободную `run-NNNN` через mkdir; существующий каталог пропускается по EEXIST, при других ошибках тест не начинается. Все диагностические output paths строятся внутри выбранного нового каталога. Сохранение предыдущего run также уже проверялось в Azahar.

## Один запуск

1. Перед тестом скопировать существующую `SD:/3ds/ds34-gx-watch-v0.2.0/` на ПК как резервную копию. На SD её не удалять и не заменять.
2. Скопировать новую CIA на SD, установить через FBI. Открыть из HOME именно **DS34 UV Mask 0.2.1**, TitleID **000400000FDE6F00**. Старый GX Watch не запускать.
3. На экране READY записать/сфотографировать новый номер `Run: run-NNNN`. Нажать **A один раз**. Наблюдение занимает до2 секунд, затем выполняется запись на SD; дождаться **06 OBSERVATION SAVED** и сфотографировать оба экрана.
4. Ожидаемый полный PASS: белый прямоугольник на голубом фоне, **PSC0/P3D/PPF=1/1/1**, **Q total/sub/done=3/3/3**, **Pixel check: OK**. Нажать **START один раз**, отметить, вернулось ли приложение в HOME.
5. Если busy/FAIL/полная остановка — сфотографировать последний экран. При отказе выхода использовать POWER, как в предыдущем испытании. **Повторно приложение не открывать и повторный тест не запускать.**
6. После завершения/выключения скопировать с SD **весь новый `run-NNNN`** без редактирования: `gpu-test.log`, `observation.json`, `first-frame.pica`, `result.json`, `ready.txt`, а также все имеющиеся `frame.raw`, `late-*.json`, `exit.txt`. Если файлов меньше, сохранить папку как есть. Передать архив новой run-папки, фото и результат START/HOME или POWER. Надёжнее дополнительно сохранить весь versioned SD root как архив.

Корень остаётся `SD:/3ds/ds34-gx-watch-v0.2.0/`, но сама run-папка отдельная. Если run-0001 существует, будет выбрана следующая свободная; не предполагать номер заранее. Экран/log/result version остаётся0.2.0 намеренно ради идентичности CPU ELF. При идентификации использовать новую HOME identity, hash CIA и номер run.

P3D без PPF/правильного кадра/нормального выхода — частичный результат. Прежние1/0/0 и3/3/1 опровергнут достаточность этой правки как единственного исправления. При полном PASS следующий этап — перенос двух shader-правок в основной backend и подготовка оригинального игрового кадра. До фактического результата аппаратный успех не заявлять.
