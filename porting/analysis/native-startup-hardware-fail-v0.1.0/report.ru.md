# Аппаратный FAIL малого startup — 31.10.2026

Пользователь сообщил: «опять не сработало, всё так-же, как и до этого». Предыдущий случай — чёрные экраны и отсутствие реакции. На отдельный вопрос о `SD:/3ds/ds-native-startup-v0.1.0/` ответил: **«Папки нет»**. READY/возврат в HOME не подтверждены. Фото, журнал и измерение идентичности установленной CIA не получены; способ выключения нового запуска отдельно не уточнялся. Ожидаемый файл — startup0.1.0, TitleID000400000FDE7200, SHA256 `4ae98b7dd2f59df827b9e3f5ad966e4abe2896db538c65be3bf18832ac27fa7c`.

Агент не запускал аппаратное обеспечение. Повторный запуск не разрешён. Отсутствующие логи снова не запрашиваются. Новая CIA в этом обновлении не создавалась.

## Что этот результат меняет

Уменьшение ранних куч с40+132 до2+2MiB не устранило наблюдаемый симптом. Поэтому **172MiB не объясняют оба FAIL**: в малом тесте такого запроса нет. Это не доказывает достаточность памяти h2 — у него всё ещё может быть собственный дополнительный memory blocker. Рабочая гипотеза «уменьшить кучи и тем самым исправить аппаратный startup» не получила подтверждения.

В startup вообще нет оригинального движка, donor workers, RX loader, DS34 и PICA submissions. Они не могут быть необходимой причиной зависания малого теста. Причину игрового FAIL нельзя автоматически считать идентичной только по одинаковым чёрным экранам.

Отсутствие READY и папки **не доказывает**, что main не достигнут: остаются launch/CRT/heap/services, main/gfx/console и ошибка/остановка SD. Первая запись SD происходит после попытки отобразить READY. Аппаратные memory counters по-прежнему не получены.

## Статическое сравнение с аппаратным PASS

Заново разобран фактический UV Mask CIA, его exheader сопоставлен с сохранённым exheader startup CIA. В RSF, помимо title/product/ID, различаются ровно три группы настроек:

| Поле | Hardware-PASS DS34 UV Mask0.2.1 | Hardware-FAIL Startup0.1.0 |
|---|---|---|
| New3DS memory mode | Legacy/64MB | 178MB |
| Kernel release | 2.33 | 2.44 |
| Дополнительные SVC permissions | отсутствуют | 0x54,0x70,0x7d |

Остальные параметры RSF, включая filesystem/services, dependency list, priority, affinity и stack, совпадают. Сравнение access-control bytes сохранено отдельно: перестановки слов capabilities при добавлении SVC не следует считать независимыми неизвестными настройками. [RSF diff](startup-vs-hardware-PASS.rsf.diff), [фактический access-control diff](access-control-byte-diff.json), [UV Mask container audit](uv-mask-container-audit.txt).

Различия режима/kernel/SVC были сохранены в малом тесте намеренно, чтобы менять размер куч без одновременной замены профиля. Теперь размер куч не дал успеха, и **следующий приоритет — профиль запуска**, а не shader или donor shutdown. Неправильность какого-либо поля пока не доказана. У startup есть и собственная pre-main measuring wrapper; весь его executable не идентичен DS34, поэтому сравнение двух приложений не является доказательством единственной причины.

## Один следующий изолированный эксперимент — только после согласования

Для проверки memory mode взять **тот же ELF startup0.1.0** с теми же2+2MiB, wrapper, kernel2.44 и SVC permissions. Из функциональных параметров упаковки изменить только **SystemModeExt178MB → Legacy**; необходимые идентификаторы новой диагностики учитывать отдельно. Не добавлять новую обвязку, не менять kernel и SVC одновременно с memory mode. Донор и GPU backend не нужны.

- READY+START→HOME при подтверждённой идентичности установленного файла покажут, что смена memory mode устраняет FAIL этого startup. Затем потребуется объяснить совместимость расширенного режима для полного игрового бюджета; 172MiB в Legacy64 не помещаются.
- Те же чёрные экраны оставят kernel/capabilities/CRT/services/gfx и прочие ранние зависимости открытыми. Не выполнять автоматические повторения и не менять несколько полей вслед за FAIL.
- Успех в Azahar проверяет упаковку и отсутствие программной регрессии, но не выбирает аппаратную причину.

Этот эксперимент **не собран и не запускался** в текущем обновлении. Сначала зафиксирован результат уже выполненного пользователем теста и сделано сравнение. Ни одна игровая или startup CIA не объявляется аппаратно рабочей. Старые Azahar PASS сохранены как исторические software results.
